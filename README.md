# Сайт Александра Белякова — техническая документация

Этот файл — справка для владельца сайта (не программиста) и для новой сессии Claude Code, чтобы быстро понять структуру и историю проекта без необходимости пересматривать всю переписку.

## 1. Общее описание

- **Что это:** лендинг частного специалиста по Яндекс Директу (Александр Беляков).
- **Домен:** `direct.alex-belyakov.com` (задаётся файлом `CNAME` в корне репозитория).
- **Репозиторий:** https://github.com/Aleksandr-Beliakov/direct
- **Хостинг:** GitHub Pages, статический сайт без сборки — чистый HTML/CSS/JS, без npm/фреймворков.
- **Шрифт:** Google Fonts «Golos Text», подключается на каждой странице через `<link>` в `<head>`.
- **Стиль вёрстки:** большая часть оформления — инлайн `style="..."` прямо в HTML (так исторически сложилось при переносе из макета Claude Design). В `css/style.css` вынесены только адаптивные media-запросы и несколько именованных компонентов (FAQ-аккордеон, попапы).

Во всех живых попапах-заявках (`forma-audit`, `forma-obsudit`, `forma-zakazat`, `forma-mediaplan`) над полем телефона стоит ряд из 3 кнопок-ссылок «Написать в мессенджер» (Telegram / MAX / WhatsApp, ведут на `t.me/a_beliakov`, `max.ru/...`, `wa.me/79890473181`) — это не часть формы, просто быстрый способ написать напрямую, минуя отправку заявки.

Общие для всех форм технические поля:
- `consent` — чекбокс согласия на обработку персональных данных. **Обязателен**: без галочки форма не отправится, рядом появится подсказка.
- Поля, помеченные выше как «обязательно», тоже не дают отправить форму пустыми — браузерная стандартная подсказка отключена (`novalidate`), вместо неё показывается своя подсказка на русском рядом с кнопкой и подсвечивается конкретное незаполненное поле.
- `subject` (скрытое поле) — пишет в письмо, какая именно форма/страница прислала заявку, например «Заявка с сайта — попап «Заказать настройку»». Без этого поля все письма выглядели бы одинаково.
- `botcheck` (скрытое поле-ловушка для ботов, honeypot) — см. раздел 4.

## 4. Как устроена отправка форм

- **Сервис:** [Web3Forms](https://web3forms.com) — сторонний сервис приёма форм без бэкенда, письмо с содержимым формы приходит на почту владельца ключа. Общий для всех форм access key хранится прямо в `js/forms.js` (не в этом файле — ключ намеренно не публикуется в документации).
- **Как работает `js/forms.js`:** один общий скрипт находит на странице все `<form data-redirect="...">`, при отправке:
  1. Проверяет обязательные текстовые поля (`required`, но с отключённой браузерной подсказкой через `novalidate`). Если что-то пустое — форма не отправляется, показывается своя подсказка на русском, и фокус ставится на первое незаполненное поле. Поле `email` дополнительно проверяется на формат (должно быть похоже на настоящий email), поле `phone` — на формат телефона (только цифры/пробелы/`+`/скобки/дефисы, и 10–11 цифр внутри), иначе — своя подсказка «Введите настоящий email/номер телефона, например ...».
  2. Проверяет чекбокс `consent`. Если не отмечен — форма не отправляется, показывается подсказка рядом с галочкой.
  3. Собирает все реально существующие поля формы через `FormData` и отправляет POST-запросом на `https://api.web3forms.com/submit`.
  4. Если Web3Forms ответил успехом — в `window.dataLayer` пушится событие `{ event: 'form_sent', form_id: '<id формы>' }` (для аналитики/целей в Метрике или GTM), и браузер переходит на адрес из `data-redirect` (сейчас у всех живых форм это `thanks.html`).
  5. Если сеть недоступна или Web3Forms вернул ошибку — кнопка возвращается в исходное состояние, рядом с формой показывается текст «Не получилось отправить, напишите мне напрямую в Telegram» со ссылкой на https://t.me/a_beliakov.
- **Поле `subject`** — задаёт «тему» письма на стороне Web3Forms, по нему в почте сразу видно, с какой именно кнопки/попапа пришла заявка.
- **Honeypot (`botcheck`)** — скрытый чекбокс, невидимый обычному человеку (`display:none`), но который боты-скрипты иногда всё равно заполняют. Web3Forms распознаёт такие отправки как спам и отсекает их. Реализовано на всех формах сайта.
- **Куда приходит почта:** на адрес, привязанный к access key в личном кабинете Web3Forms (настраивается на их стороне, в коде сайта этого адреса нет).
- **Событие `form_sent`** — если на сайт подключат Google Tag Manager или используют цели Метрики через dataLayer, это событие уже пушится при каждой успешной отправке любой из живых форм, с полем `form_id`, по которому можно различать, какая именно форма сработала.

## 7. Индексация поисковиками (временно отключена)

Пока идёт подготовка сайта, индексация в поисковиках **намеренно закрыта**:
- На всех живых страницах сайта в `<head>` стоит `<meta name="robots" content="noindex, nofollow">`.
- В корне репозитория лежит `robots.txt` с `Disallow: /` для всех роботов.

Сайт при этом работает как обычно — это не блокирует доступ людям по прямым ссылкам, только просит поисковики не добавлять страницы в выдачу. **Когда сайт будет готов к запуску, оба этих ограничения нужно снять** (убрать мета-тег на всех страницах и поправить/удалить `robots.txt`), иначе сайт так и не появится в поиске.

- **Яндекс.Метрика + баннер согласия на cookie** — счётчик (id `111606163`) больше **не** вставлен напрямую в `<head>`. Вместо этого на каждой странице перед `</body>` подключён `<script src="/js/cookie-consent.js" defer></script>` (путь абсолютный от корня — работает одинаково на страницах любой вложенности).
  - При первом визите показывается компактная тёмная карточка (не на всю ширину, плавает снизу слева) с текстом, ссылкой на `/privacy.html#cookies` и одной кнопкой «Принять». Кнопки «Отклонить» нет — согласие даётся явным кликом или продолжением пользования сайтом.
  - Согласие сохраняется в `localStorage.cookie_consent = 'accepted'`. Пока пользователь не нажал «Принять», карточка показывается на каждой странице.
  - Код счётчика Метрики (те же id и параметры, что были раньше) теперь живёт внутри функции `loadAnalytics()` в `js/cookie-consent.js` и вызывается только при нажатии «Принять» или если согласие уже было дано ранее. При отказе или до выбора — счётчик не грузится вообще.

  - **При создании любой новой страницы сайта** счётчик в `<head>` добавлять не нужно — достаточно подключить `js/cookie-consent.js` перед `</body>`, как на остальных живых страницах.
